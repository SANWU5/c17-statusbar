# 统一插件详情页规范

新插件以“更好的玻璃”的 **说明、设置、管理** 三页为交互基准。页面、作用域申请与重启由 C17 统一提供，插件声明自己的功能、配置、状态和操作。API 2 开发模板以 **宿主 code261** 为基线，见 [standard-runtime](../templates/standard-runtime/README.md)。本文规定通用行为，不分发业务插件代码。

## 说明：使用方法与作用域

| 界面内容 | 插件作者提供 | 宿主行为 |
|---|---|---|
| 使用说明 | `usage` 写顺序、生效条件、影响区域和恢复方法 | 优先展示 usage，缺失时回退 description |
| 版本与兼容性 | `minimumHost`、实际依赖的 `features` | minimumHost 展示版本要求；**features 才是当前能力准入检查**，不能漏声明能力 |
| 作用域 | `scopes` 精确包名 | 展示实际勾选状态；查询失败为未知 |
| 一键申请作用域 | 无需自建 action | 通过框架申请缺少的作用域，等待并复查；取消等待不等于撤销已授予的作用域 |
| 一键重启作用域 | 无需自建 action | 使用已取得的 Root 权限处理有效作用域目标，分别报告成功或失败 |
| 作者、来源、版本、时间 | 身份与版本元数据 | 在说明页统一呈现 |

作用域申请、插件启用和进程就绪是不同状态。框架断开、目标未安装、未授权和运行未就绪须区分。重启会中断对应应用，用户主动点击后才执行，不能改参数就自动重启。API 2 多应用需要 `scope.apps`，不支持 `android` 系统服务或 C17 自身。旧包缺少 scopes 时沿用原 SystemUI 环境。

## 设置：一个总开关，按功能分类

宿主在设置根页提供唯一的“启用插件”总开关。插件可以有控制独立功能的开关，例如“自由编辑”“媒体壁纸”，不要再创建覆盖全部功能的总开关。

新表单明确声明 `section:"features"` 和 `groupPath`。路径最多三层，每层按首次出现顺序排列；同路径控件先显示，子分类随后显示。进入子页后标题和返回跟随分类；切换说明/设置/管理页时回到根页。

| 功能复杂度 | 分类示例 |
|---|---|
| 少量设置 | 记录设置、记录设置 → 备注 |
| 编辑控制中心 | 布局与编辑、全部磁贴、媒体卡片 → 媒体壁纸 |
| 多场景玻璃 | 桌面 → Dock、锁屏 → 锁屏时钟，参数收进对应功能的效果页 |

不为凑分类制造空页面，也不照抄其他插件的全部目录。一个参数只有一个权威 key；移动分类、改标题或改插件名称时保留 key、类型和有效值。

- 开关给出真实默认值；新功能默认关闭，升级不清零用户已有设置。
- slider 的范围、输入、单位和默认值一致；只有确实允许超范围才声明 `unboundedInput`，百分比不应全部取消范围。
- color、app、select、sort 使用宿主控件。动态排序保留稳定标识和离线项目。
- `enableOnEdit` 明确关联需要自动开启的功能，不暗改其他场景或主 App。
- `action` 执行一次，`status` 展示运行报告，均不写入持久配置。旧 button 是赋值控件。

声明 `ui.group-paths`；管理页也使用分类时另声明 **`ui.management-groups`（code261）**。旧 group 分组仍兼容；`ui.collapsible-groups` 控制旧式分组折叠，不代替 groupPath 菜单。

## 管理：插件维护分类与宿主公共操作

维护控件声明 `section:"management"`，使用与设置页相同的 groupPath。常见分类为“运行状态”“安全回退”“数据管理”，按功能需要添加。状态来自实际结果；刷新只更新观察，不反复重载 DEX 或重装 Hook。不可恢复操作通过 `action.confirmation` 说明具体影响。

管理根页在插件分类之后统一提供：

- 相关宿主设置（存在匹配项时显示）。
- 恢复默认：恢复表单默认值、保留启用状态，不等于恢复原厂布局或清除独立存储。
- 从文件更新：复用导入、身份核对和升级流程。
- 删除插件：由宿主管理安装与归属数据清理。

公共操作只放根页，不在每个子分类重复，也不能由插件重做同名按钮。原生布局插件应额外提供自己的安全回退，明确能保存或恢复哪些内容；恢复默认不能冒充布局备份恢复。

## 兼容、工具与交付

新开发复制 API 2 模板，旧 API 1 模板保留。整理现有插件时先核对 ID、持久 key、默认值和存储归属，再递增 versionCode；更名不更换 ID、不删数据重装。

```powershell
python tools/pack.py standard templates/standard-runtime
python tools/pack.py build templates/standard-runtime --out dist
python -m unittest discover -s tests -v
```

标准构建器要求严格 JSON 的元数据头和 ui 数组，**不执行 JavaScript**。动态表单由真实宿主执行并导出描述，再用 `descriptor --manifest ... --standard` 核对元数据与表单；不替代真实导入、settings/hooks 语义和手机适配验证。完整要求见 [验收清单](VALIDATION.zh-CN.md)。

宿主历史上对编辑插件的壁纸键有兼容入口，那不是通用素材 API。第三方不能借用业务 key；需要新能力应先扩展宿主契约和能力声明，再使用自己的命名空间。
