# 插件运行与交互验收指南

## 统一详情页验收（code261）

- **说明**：usage、版本与真实作用域一致；框架断开、未勾选、目标未安装、拒绝授权都显示实际状态；申请仅处理缺少的作用域；取消等待不撤销授权。
- **重启**：无 Root、无有效目标和部分失败有准确反馈；只处理当前插件的有效目标；保存的设置与其他插件不被重置。
- **设置**：只有一个插件总开关；功能开关保留；类别和子类别可进入、返回；切换页签回到根页；数值/颜色/应用/排序保存后重开一致。
- **管理**：状态与安全回退分类可进入；公共恢复默认/更新/删除只在根页；刷新不触发业务重装；风险操作确认说明准确。
- **升级**：改名称与分类后 ID、每个有效 key 和独立数据保留；API 2 更新默认停用，按原流程启用，不静默信任新代码。
- **性能**：通过事件更新配置和状态；局部修改不重复加载 DEX，不常驻轮询；实机卡顿和帧率须独立测量，不能用结构检查代替。

工具测试可运行 `python -m unittest discover -s tests -v`。这验证打包/表单/协议及反例；真实宿主和手机检查需要另行记录版本、结果与未覆盖项。


本文是通用黑盒验收约定，配合[分发规范](../SPEC.md)、[SDK](SDK.zh-CN.md) 与[发布说明](PUBLISHING.zh-CN.md) 使用。它不提供业务实现、不增加 API 或协议字段，也不表示任何插件或 ROM 已经通过测试。只验收插件实际提供的功能，不适用项应注明原因。

## 记录与判定

记录宿主、插件、Android 与 ROM 的版本、功能开关、初始页面、操作步骤、预期和实际结果。分别标明桌面检查、真机观察、未验证与失败；构建成功或导入成功不能替代交互测试。

录制页面切换时先确认当前页和编辑状态，避免录制期间的并发操作改变场景。明确区分编辑、普通页面、通知页面与其他前台应用；混合场景不能记为连续切换通过。报告可描述裁切、松手跳变与动画连续性，不能只凭最终截图或位置数值判断中间过程正常。

公开报告只保留脱敏步骤与结论。不得提交通知内容、账号、设备标识、原始备份、壁纸、截图中的私人内容、密钥或无权分发的 OEM 材料；敏感问题按[安全政策](../SECURITY.md) 处理。

## 配置简洁与升级兼容

1. 检查名称能否直接表达用途，说明只保留生效条件和必要提示；详细帮助可从文档访问。
2. 将全部可调项与旧版逐项对照。精简文字后，键、类型、选项值、默认值和范围仍须符合兼容约定，参数不能被悄悄隐藏或删除。
3. 预先保存不同于默认值的有效配置，再升级并读取。确认数值仍在、含义一致；升级默认停用的约定不变。另行验证恢复默认，并确认不会改写用户主配置或其他插件设置。
4. 把需要新版宿主的接口要求写入发行文档。不能因文案变短而删掉最低宿主、恢复入口与已知限制。

## 详情、作用域与原生设置

1. 详情始终按前置条件（使用说明与概况、作用域）、完整功能与设置、插件管理排列；核对全部旧开关和入口仍可访问。用非默认配置验证改变控件顺序、`section/group` 后按 key 保留值，管理段持久控件仍可编辑，动作与状态不进入配置。字段映射见[详情三段布局](DETAIL-UI.zh-CN.md)。
2. 分别核对声明作用域、框架实际勾选、插件启用与运行就绪。框架结果无法取得时显示未知；未声明作用域的旧包仍能使用原有 SystemUI 环境。
3. 对当前引擎不支持的应用执行作用域，允许保留导入审阅，但须显示不支持并阻止启用。框架已勾选该应用也不能变成运行通过结论。
4. 分别测试最低宿主不足、所需能力缺失与全部满足，信息须对应真实条件。普通插件业务更新不应无故要求升级宿主；目录保持基本元数据，新详情信息须在 manifest 与真实描述中一致。
5. 如有原生设置，使用包含真实入口资源的 ZIP 进入页面；在停用时编辑有效参数，确认异步保存和错误回调不会卡住主线程，也不能写入未声明的 key。
6. 保存中退出、更新或删除插件，再等待旧回调：旧页面不得复活或覆盖新状态。重新进入读取最新值，清理监听器和任务；核对页面在 App 进程运行，不把它记为其他应用执行通过。
7. 在一次成功的作用域查询后模拟失联或查询失败，应显示未知；再取得成功空列表，应显示未勾选；重新选择后应显示已勾选。旧查询结果、插件 state 与启用状态均不能替代当前框架证据。

## 异步测量与布局等待

| 场景 | 预期行为 |
|---|---|
| 首次打开时尺寸未知或尚不可容纳扩展 | 保持可访问的原生界面，不使用猜测尺寸强行提交 |
| 之后尺寸就绪且没有新业务事件 | 相关几何变化可触发重试，不需要用户反复切换开关 |
| 几何不变的连续帧 | 不反复提交布局、请求布局或重启动画 |
| 快速进入/退出编辑、收起再展开 | 最终状态与用户最后操作一致，草稿与撤销历史不因等待丢失 |
| 停用、解绑、旋转或替换运行实例 | 旧回调失效，不重新应用旧布局；当前实例按实际条件工作 |
| 始终无法满足空间或契约 | 保持原生回退，并如实显示限制，不无限重试 |

必要时使用脱敏计数确认重复提交与布局请求是否持续增长。等待可以观察几何，但不能把观察本身变成每帧重渲循环；一次失败后永不重试也不符合尺寸后来就绪的场景。

## 所拥有视图的停用与复用恢复

在启用前记录原生外观和访问路径；启用后改变尺寸、顺序或形态，再停用、移除、解绑、重新进入与重复启停。安全模式应另行验证，因为它会停止插件运行。

检查外层格子、内部内容宽高、子视图数量、文字、触摸、监听器和滚动状态。外层恢复而内部仍保持扩展宽度、重叠旧子视图或点击命中偏移，均属于恢复失败。覆盖新建视图和相同尺寸的复用视图，避免仅因尺寸相等跳过必要恢复。

恢复范围必须限于插件确认拥有且实际修改的对象。其他插件、候选区、原生视图与未知监听器应保持其归属；不能通过清空整个池、删除不认识的子视图或全局重置属性来获得表面一致。普通受管 Hook 的撤销与视图内容恢复应分别验证。

## 媒体拖动与原生提交

使用可定位进度且支持拖动的媒体会话，分别测试点按、慢拖、快速拖、松手与取消，覆盖其他横滑手势可能竞争的区域。触摸进度区域以外时，原页面手势仍应正常。

进度预览改变不等于媒体已定位；松手时的即时位置也可能仍是旧回报。若沿用原生控件，应等待原生拖动或回弹结束，并在事先约定的有界观察窗口内核对控制器与播放器后续位置；窗口应覆盖目标 ROM 的原生收尾过程，不能无限等待。区分自然播放增加的时间与实际定位。部分控件的拖动结果包含相对位移或惯性，不应直接以手指终点百分比断言最终目标。

记录是否提交、提交后位置是否收敛以及取消是否正确；不要为弥补预览与回报的时间差发送第二次定位。无法获得可信控制器回报时应列为未确认，而非仅凭进度条宣布成功。停用或取消后，原生滚动与父级手势应恢复。

## 相同封面与背景复用

在同一封面下反复播放、暂停，并等待几个进度更新周期。封面与其他实际背景输入均未变化时，不应因播放状态或进度改变而重建背景、重启过渡或闪烁；对象重新分发但图像内容相同的场景也应覆盖。

随后改变封面及插件声明会影响背景的设置，确认需要的刷新仍会发生；清除媒体和停用后应恢复原生外观。验收可记录刷新与动画启动次数，但不能公开媒体内容或图像数据，也不能把“少刷新”等同于任何输入都不更新。

## 字体测量与超长文字

使用长标题、长歌手名、中文、拉丁字母、数字、上下延伸笔画和不同系统字号测试各形态。时间、进度和操作区应按实际字体度量与内边距留足高度，不能只靠固定框高或缩小字号掩盖裁字。空间不足时回退应保持可访问，文字与触摸区不得互相覆盖。

需要自动滚动的超长单行文本应可持续完整阅读。相同内容的重复布局和状态更新不能把滚动持续拉回开头、反复写入同值配置或触发不停止的布局请求；更换内容时仍应正常更新。

切换形态、无媒体、停用、解绑与重新绑定后，核对截断方式、选中状态、行数或像素高度模式、横向滚动、重复次数与滚动位置等被修改属性能否恢复。保留原生绑定期间产生的新状态，不以更早快照覆盖当前原生内容。

## 发布前结论

在发行说明列明实际完成的场景、测试环境、已知限制和待验证项。保留旧失败与新通过的本地证据有助于复核，但公开仓库只接收有权分发且已脱敏的内容。按[本地构建与正式分发](PUBLISHING.zh-CN.md) 运行适用检查；本指南通过不改变当前空目录，也不会自动生成或发布插件包。
