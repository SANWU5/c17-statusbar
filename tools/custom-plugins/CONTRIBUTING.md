# 贡献与收录要求

提交前请阅读 [规范](SPEC.md)、[SDK](docs/SDK.zh-CN.md)、[安全政策](SECURITY.md) 和 [免责声明](DISCLAIMER.zh-CN.md)。当前目录有意保持为空；开发模板不会自动变成发行插件。欢迎对协议、工具和文档提出改进，也可在证据充分后提交实际插件供审查。

## 需要提供

1. 清晰用途、稳定且属于自己的命名空间、版本和最小能力声明。
2. 可读源码、确定性 ZIP、实际 size/SHA-256，避免不必要压缩混淆、下载器和外部执行依赖。
3. 包内 LICENSE 与 README：作者、来源链接、版权与依赖许可、适配 Android/ROM/构建号、宿主/API、限制、冲突和恢复方法。
4. 测试证据：结构/语义校验、默认停用、启停/升级/删除/安全模式、冲突拒绝，以及已测试设备上的效果。明确区分桌面检查与真机观察。
5. 用户可理解的变更记录；升级必须增加 versionCode，同版本不得替换不同内容。

不得提交 APK、密钥、令牌、用户偏好、手机日志中的隐私、无授权 OEM/商业资源或主程序私有源码。对引用内容保留出处和必要声明，提交者应有权按所声明许可证分发。

## 审查与发布

通过 Issue 或 Pull Request 提交。维护者会检查用途、来源、能力、真实 ROM 目标、容量和路径、规则冲突、撤销行为与风险说明；需要时要求补证据。自动检查通过不会代替人工审查，也不保证一定收录。

`build/build-all` 生成本地开发包，不更改 root index。只有明确的 `publish` 命令会准备本地 `packages/` 与 `index.json`，不会自动提交或推送。发布实际包必须通过审查后提交，目录 `file` 用 `packages/...zip`，README 和 CHANGELOG 保持可访问。

对严重漏洞、侵权、恶意或失实适配声明，可先撤回目录再调查，并在允许公开时说明处理结果。撤回不会远程卸载用户已安装的副本；修复和重新收录需新版本与复核。请尊重审查结论，争议以具体证据讨论。
