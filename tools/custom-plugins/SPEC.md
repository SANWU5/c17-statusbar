# C17 扩展插件分发规范 · API 1/2

## 新插件的统一交互基线

新 API 2 插件采用 [统一详情页](docs/DETAIL-UI.zh-CN.md)：说明页由宿主提供作用域申请与重启；设置页以唯一插件总开关和功能分类组织；管理页容纳插件维护分类，公共恢复默认、更新、删除保留在根页。依赖管理分类的包声明 `minimumHost:261`、`ui.group-paths` 和 `ui.management-groups`。仅更名不改变 ID，分类调整不改变持久 key；升级必须验证全部有效值保留。

`minimumHost` 是版本说明，当前宿主以 `features` 做能力准入。不要仅填写最低版本却遗漏使用的能力。标准开发检查用 `pack.py standard`，动态输出用 `pack.py descriptor`，真实导入与手机适配仍必须验证。


本文与 [SDK](docs/SDK.zh-CN.md)、`schema/` 的机器可读协议及宿主实际校验共同构成开发约定。宿主不会因目录已收录而绕过导入和启用检查。

## 格式与版本

单文件是 UTF-8 `.js`。ZIP 根目录必须有 `plugin.json`，`entry` 指向生成身份和设置表单的 `.js` 元数据入口。API 1 只执行此入口，不提供多文件模块加载，包内只允许小写 `.js/.md/.txt`、根 `plugin.json` 和 `LICENSE` 等宿主支持的文本。API 2 还须在 manifest 和元数据声明相同的 `runtime.entry` 或 `runtime.source`，且 capabilities 包含 `runtime`；运行入口在主动启用后执行，可附带 DEX、图片、字体等二进制资源，以及 code291 起的 `i18n/<语言>.json` 界面翻译表（见下文“界面翻译”）。在线索引的插件条目只列分发元数据，不含 `runtime` 源码或入口。容量、路径和计算边界见 SDK。

`id` 稳定且全局唯一，长度 3–80，格式 `[a-z][a-z0-9]*(?:[._-][a-z0-9]+)*`。建议用自己控制的反向域名、项目或账号空间，例如 `io.github.<账号>.<插件名>`；不要冒用他人名称、官方关系或更新渠道。`dev.c17.*` 留给 C17 官方开发模板及经维护者确认的官方插件。

`version` 是面向用户的版本文字；`versionCode` 是 1–2147483647 的严格递增整数，升级必须更大，不得用同版本替换不同内容。API 1 保持隔离的声明式设置和规则；API 2 提供完整 Java/Android 运行扩展，需要支持 API 2 的宿主。不得在同一 API 下偷换字段语义。

manifest 中声明的元数据、能力应与脚本输出一致，不得因用户状态暗中变更。插件自身的版本、API、主应用版本和目录 `schemaVersion` 是不同概念。

API 2 的接口会随宿主增加，不能只凭 `apiVersion:2` 判断所有功能可用。`action/status` 表单和 `C17.onAction/publishStatus` 最低需要 Status C17 2.1.0_beta.008 / code206；code205 及更早的 API 2 宿主不能导入含这些控件的插件。code210 起增加下表的可选展示与能力契约，API 编号仍为 1/2；旧插件可以保持原声明和原最低宿主，不要求仅为普通业务更新升级宿主。本规范不表示 code210 已发布、安装或通过目标 ROM 验收。

| 可选字段 | 约定 |
|---|---|
| `minimumHost` | 1–2147483647 的整数，表示所需主应用 `versionCode`；不是插件版本 |
| `features` | 至多 64 个唯一的宿主能力标识，每项最多 80 字符，格式与插件 ID 相同；只列确实需要的能力 |
| `usage` | 最多 4096 字符的使用说明、影响区域、适配条件与恢复概况 |
| `scopes` | 至多 64 个唯一 Android 包名，每项最多 240 字符，旧元数据语法接受 `android`，但运行引擎不支持该作用域；表示声明的应用作用域，不是勾选结果、授权或进程启动指令 |
| `nativeSettings` | 仅 API 2；`{"dex":"settings.dex","className":"example.plugin.SettingsView"}`，指向包内原生设置入口，详见 [SDK](docs/SDK.zh-CN.md#原生设置入口) |
| `configurationAliases` | code265 起，仅 API 2；旧配置键到当前持久控件键的对象，最多 512 项，须声明 `minimumHost:265` 或更新版本与 `config.aliases` 能力 |

使用这些新字段或控件分组需要识别它们的宿主，发行说明仍须写清最低宿主。不得把不存在的接口名写成已提供能力。`minimumHost/features/usage/scopes/nativeSettings/configurationAliases` 在 manifest 与真实脚本输出之间必须一致；旧目录仍只发布基本分发元数据，不应手工加入这些字段。

`configurationAliases` 只在导入版本号更早的插件配置 JSON 时生效，例如 `{"old_strength":"strength"}`；不会新增表单控件或持久状态。源键必须是合法且不与当前任何控件键重叠的旧键，目标必须是当前持久控件；禁止同键映射、串联、循环及多个源键共用目标。旧值按目标控件类型与范围验证；同一配置文件同时提供旧键与当前键时，当前键优先，旧值仍须合法。未声明的未知键、来自当前版本的旧键及更新版本配置仍会被拒绝。升级安装保留当前支持的键，独立配置导入按上述别名迁移；这两条路径都须验证。完整规则与示例见 [SDK](docs/SDK.zh-CN.md#旧配置键迁移code265)。

## 能力与适配

**每个新导入、升级或提交仓库的插件都必须提供完整设置。** 普通表单必须在 `ui` 逐项声明用户可调整的功能参数，至少包含一个真实关联功能的 `switch/slider/input/select`；缺少设置入口、只有说明或只有执行按钮均不符合规范。API 2 可用有效 `nativeSettings` 提供完整设置入口，此时 `ui` 可以为空数组；使用宿主表单状态的参数仍须声明相应有状态控件。不得添加与功能无关的占位开关来规避要求。设置应覆盖插件全部可调行为，写清默认值、范围、当前生效条件及恢复方式。结构校验不等同于参数覆盖完整性审查。

配置界面应使用简短名称和必要说明，把详细适配、诊断与恢复步骤放入可访问的文档。精简文案不等于删除参数：现有设置键、类型、选项值、默认值与有效范围应保持兼容，不能借界面整理重置用户值、隐藏可调行为或改变旧参数语义。确需不兼容迁移时须明确记录迁移规则与恢复方式，按升级流程验证。

插件详情固定按三段组织：①前置条件，包含使用说明与概况、声明作用域和可核实的真实勾选状态；查不到时明确显示“未知”，不从插件已启用、声明或缓存推断；②功能与设置，呈现全部业务开关和入口；③插件管理，放删除、更新、恢复与其他管理设置。控件可用 `section:"features"`（默认）或 `section:"management"` 选择后两段，并以最多 120 字符的 `group` 分组。分组只影响展示，不改变参数语义或动作生命周期。作者字段与宿主职责、升级验证见[详情三段布局](docs/DETAIL-UI.zh-CN.md)；已有通用控件与原生设置 ABI 足以承载的功能不得要求按插件 ID 在宿主另加业务入口。

code196 起，宿主在新导入与升级时强制检查配置要求；已经安装的旧版无配置插件保留原记录及启用状态，显示需作者补全设置，仍可停用和移除。仓库不得因此继续分发无配置旧包；修订包须增加 `versionCode`。在线目录只存元数据，下载后仍须通过相同的真实脚本配置检查。

仅声明实际需要的能力。`settings/systemui` 是 API 1 的声明式能力；API 2 还须声明 `runtime` 并提供运行入口。API 2 会在 SystemUI 进程内执行作者代码，拥有该进程可用的 Java/Android 对象、反射、Hook、DEX、文件和线程能力，不是隔离沙箱。安装默认停用；启用前须检查源码和来源。不得隐藏真实用途、在名称和说明中伪装更新、索取与插件无关的授权或鼓励关闭安全机制。API 2 不自动获得 Root。

code246 增加 API 2 多应用执行能力。声明非 SystemUI 应用时，必须同时声明 `features` 中的 `scope.apps`、API 2 `runtime` 和精确 `scopes` 包名，最低宿主应为 246；不能同时输出 API 1 的宿主设置覆盖或系统规则。系统服务包 `android`、宿主自身包和无效包名不能启用；引擎不使用厂商包名前缀放行或通配符。未声明 `scopes` 的旧插件继续只在 SystemUI 运行。框架须实际将模块加载到目标应用，声明或启用插件不等于已获得框架作用域。控制中心、状态栏、锁屏等组件区域写在 `usage`，不能伪装成应用包名。

每个目标进程单独执行 runtime，使用真实应用 Context、类加载器与普通受管 Hook 生命周期。外部配置、资源和状态通道验证 Binder 调用 UID，仅交付该包当前有权运行的插件；不能读取宿主主设置、无关插件资源或管理命令。外部进程的素材、`C17.save/load/dataDir` 与清理归属记录按稳定进程名隔离；不限制为主进程，子进程也可运行，一个进程不能清理其他进程正在使用的文件。外部归属扫描和文件清理由已有资源工作队列串行执行，不在应用主线程等待文件锁。包含外部作用域的包不能声明非空 `runtime.preferences`，以免清除同应用共享的原生偏好文件；SystemUI 独占旧插件维持原存储契约。配置变动通过观察事件同步，不建立常驻轮询；无法取得有效配置或不能注册更新观察时保持暂停，启动暂时失败仅有限重试。宿主停用/移除插件、安全模式和可观察的宿主移除须触发清理；进程被系统直接杀死时不能承诺执行 JS 清理回调，插件仍不能永久修改系统数据来实现临时效果。

跨应用状态只允许报告当前版本与安装代次、该插件已声明的状态键，按真实包名/UID/进程隔离；详情明确显示最近报告时间，不以缓存证明仍在线。表单 `action` 保留 SystemUI 单实例执行语义，不是跨应用广播。仅含外部作用域且实际表单包含 `action` 或依赖 `optionsAction` 的 `sort` 控件时，宿主阻止启用并说明原因；仅声明 `runtime.actions` 能力而没有这些控件不会被拒绝。跨应用插件若依赖动作，必须包含实际运行的 SystemUI 作用域并自行说明该动作范围。原生设置页仍在 C17 App 中显示。code246 的 `ui.collapsible-groups` 是可选展示能力，折叠不改变参数保存、动作或恢复语义。

发行包 README 必须写清最低宿主/API、适用 Android 与 ROM/构建号、作用区域、目标类方法、已验证与未知场景、与内置功能/其他插件的冲突，以及停用和恢复步骤。只通过静态检查、AOSP 对照或桌面测试时，应如实标注，不能写成目标手机实测通过。

`settings` 只能覆盖宿主当前可见的设置，并遵守真实类型、范围。`systemui` 规则只针对精确目标；原方法仍执行，文字/属性/返回值在其正常返回后调整。同设置键或相同规则位置冲突会被拒绝。未知 ROM 应保持原生，不得使用宽泛扫描和猜测反射作为已兼容的依据。

控制中心自由编辑插件必须逐项提供所启用功能的参数、默认值和恢复方式，包括顶部行数、手动卡片尺寸许可、小磁贴提升、更多磁贴模式和音乐外观等实际使用的设置。不能只交付临时验证开关，也不能把手动调整描述成开启即自动放大。code202 起，相关业务由独立 API 2 插件实现，宿主只兼容读取旧 `qs_card_*` 声明，不再执行原布局输出；历史输出见 [SDK](docs/SDK.zh-CN.md)。API 2 的表单总项数不受 API 1 的 64 项配额限制，公共表单控件本身仍须符合 SDK 的类型和边界。涉及修改宿主未开放行为时须使用支持 API 2 的宿主；README 必须明确说明完整 SystemUI 代码执行能力及其回退边界。

一次性操作使用 `action`，只读运行文字使用 `status`。两者不进入持久表单状态，也不计入至少一个真实可编辑设置的要求；不得用修改设置计数器、固定按钮值或状态变化回调代替动作。动作绑定本次运行实例，每次显式点击才生成新请求，重载、旧实例、结果重试不能重新执行已消费请求。插件自行校验业务条件、原子保存真实数据，并在成功后发布真实状态；只读文字不是数据备份或恢复凭据。安全模式暂停整个插件，动作不例外。

涉及控制中心扩展的适配记录还必须覆盖：原生编辑与手动拖拽、原生磁贴点击/长按/分页、返回优先级、关闭后重新下拉、横屏、关闭模块、安全模式及适配失败。扩展尺寸与顺序应仅存宿主独立配置，不得把原生不支持的几何写入原生状态、缓存、Room 或原生备份。隐藏原生小磁贴前，更多入口必须已实际提交；无法提供入口时应恢复原生访问。未完成这些实测的条目必须明确列为待验证。

运行布局扩展还须验证首次测量未就绪、异步尺寸改变与视图复用。等待布局不能形成每帧重渲或持续请求布局的循环；停用、解绑和实例替换后，旧回调不得重新应用扩展。恢复只针对插件确认拥有且实际修改的视图，包含其内部尺寸、子视图和监听状态，不能只恢复外层格子，也不能改动其他插件或原生拥有的对象。通用步骤见[运行与交互验收指南](docs/VALIDATION.zh-CN.md)。这些是实现与验收要求，不增加宿主 API 或协议字段。

## 界面翻译（code291）

C17 的界面提供 30 种语言。API 2 插件可在包内附带 `i18n/<语言>.json`，宿主按用户在 C17 中选择的界面语言显示插件文字；没有翻译表的插件照常显示作者原文。翻译只影响显示：键、取值、选项 `value`、预设数值和插件存储都不翻译，宿主比较、校验和保存的仍是原文，因此翻译表不能改变任何设置的行为。

- **文件**：`i18n/` 下只允许 `<语言>.json`，语言标签与宿主一致：`en`、`ja`、`ko`、`zh-Hans`、`zh-Hant`、`es`、`pt`、`fr`、`de`、`it`、`nl`、`pl`、`ru`、`uk`、`tr`、`el`、`cs`、`ro`、`sv`、`ar`、`fa`、`he`、`ur`、`hi`、`bn`、`th`、`vi`、`id`、`ms`、`sw`，也可加地区如 `pt-BR`。至多 64 个文件；每个是 UTF-8 JSON 对象，不超过 2 MiB、20000 条，键为插件中出现的原文，值为非空译文，单条至多 8192 字符，不含 NUL，键不得重复。目录中有其他文件或格式无效时，宿主拒绝导入整个包。
- **翻译范围**：名称、简介、使用说明；表单的标题、说明、单位、选项文字、分组与菜单名（`group`/`groupPath`）、动作确认文案；运行时的只读状态文字、动作完成提示和排序项目名。
- **匹配与回退**：按整条原文精确匹配。缺少的条目依次回退到不带地区的语言、`en`（`zh-Hant` 回退 `zh-Hans`），最后显示原文。原文可以是任何语言：以英文写成的插件可提供 `zh-Hans.json`。
- **整条文字**：宿主只翻译整条字符串。运行中拼出、含变化数字或名称的文字无法匹配；应把固定部分做成独立的状态项或完整句子，或在运行脚本中按 `Locale` 自行生成。
- **元数据**：名称、简介、使用说明在 manifest 和脚本中写原文，译文只放在翻译表里；不得按语言改写元数据，manifest 与脚本一致性检查不变。
- **能力与兼容**：code291 起宿主声明 `ui.i18n`。翻译表是可选的展示数据，附带翻译表不要求声明此能力；旧宿主忽略 `i18n/` 文件，插件仍可正常导入。只有缺少宿主翻译就无法正确使用的插件才声明 `ui.i18n` 与 `minimumHost:291`。
- **打包**：`pack.py` 校验翻译表；原文清单等翻译工作文件不要放进 `i18n/`。API 1 包不支持翻译表。

仓库 MIT 仅覆盖本仓库有权许可的原创内容。第三方插件可使用明确、合法且允许分发的独立许可；提交者应说明与引用依赖的兼容关系。没有清晰来源或授权的包不予收录。

## 目录与完整性

根 `index.json` 使用 `schemaVersion:1`、`apiVersion:1` 或 `2`、`plugins` 数组（最多 128 项）；当前空数组是有效目录。目录 API 版本须覆盖其中最高插件 API。顶层可有 `name/description/updatedAt/readmeUrl/changesUrl`。README 和更新记录链接可用 HTTPS 或相对根目录路径。

每个插件目录条目只允许元数据 `id/name/version/versionCode/apiVersion/description/author/capabilities` 加 `file/sha256/size`。`file` 使用相对于索引的安全路径，例如 `packages/<id>-<versionCode>.zip`；不得是绝对 URL，不得含 `..`、反斜杠、查询或片段。`sha256` 是小写 64 位十六进制。API 1 ZIP 最大 1MiB；API 2 使用宿主和 Java 字节数组可表示的包长度，不套用 API 1 容量配额。API 1 包是受限 UTF-8 文本；API 2 可附带二进制资源，仍须是合法且安全路径的 ZIP。

在线目录与包内脚本求值后的 `id/name/version/versionCode/apiVersion` 必须逐项完全一致；目录声明了非空白 `author` 时，作者也必须一致。`description` 用于目录展示，当前客户端不按它做包身份一致性比较；发布者仍须如实描述包内功能，不得用不同描述隐藏用途。`capabilities` 必须与包内能力**按集合完全一致**：目录未写时按 `[]` 处理，不能表示“任意能力”或“由包自行决定”。例如包声明 `["settings"]`，目录却省略 capabilities、写 `[]` 或只写 `["systemui"]`，客户端都会取消导入，即使文件大小和 SHA-256 正确。manifest 与脚本之间的身份校验仍单独进行，不能用目录条目替代。

客户端按大小和 SHA-256 核对下载，再进入导入预览。哈希只能发现传输或分发内容变化，不能证明作者身份、代码安全、版权合法或 ROM 兼容。收录之前仍需代码和来源审查，用户仍需确认并主动启用。
