本轮尚未获得完整实机结论的重点：

1. 安全模式保持开启后重启 SystemUI，再关闭安全模式且不重启，立即核对 QS 与通知页恢复，确认启动时原生来源和进度观察未漏绑定。
2. 用真实蜂窝流量取得原生箭头显示的阳性对照，再退出安全模式核对强制隐藏；临时关闭蜂窝功能主开关后仍应隐藏，并恢复测试前网络与配置。系统自身没有显示箭头时，不能以“没看到箭头”证明修复通过。
3. 横屏到竖屏、展开时锁屏再解锁、QS 与通知页切换，以及 20%–60% 半程快速反向。对关闭终点闪烁和 18dp 位移，应使用覆盖完整图标路径的更高帧率材料。
4. 真正无 LSP 的 Root 保存场景，需要排除 App 旧服务连接与 SystemUI 旧进程后单独验证，不能与本轮框架已连接混写。
5. 后续酷安细节微调、新磁贴功能和新圆角方案，由主代理用新包继续核对。

源码审核仍保留两个未在本段录屏复现的边界风险：原生主动写入 `alpha=0` 与模块抑制的零值难以区分，释放时可能恢复先前非零值；关闭终点透明覆盖与 Phone 来源交接可能产生短跳变。OEM 精确锚点或原生来源不可用时会退回原生绘制，该回退也须以具体设备行为为准。

### 后续横向切页确实复现重影，已进入新一轮修复

上述纵向录屏检查之后，用户补充了横向翻页问题。主代理的 `user-page-after-left.png` 及 `horizontal-bug.mp4` 确认：通知页与 QS 整体横切时，右侧存在两组同高度、水平错位的图标。`horizontal-motion-contact.png` 的约 6.3、6.6、6.9、8.4、8.7、9.0 秒可见重影；同段录屏中底部磁贴分页未观察到同样重影。先前纵向有限观察不能覆盖此已复现场景。

设备 APK 的 DEX 证实 `SystemIconFakeFrame.dispatchDraw` 直接调用 `getMView().draw(canvas)`；`ClockFakeFrame` 继承的基类及 `NotificationFakeFrame` 也存在直接来源绘制。因此，仅抑制来源普通 alpha 不能阻止这条副本路径。

本地源码已新增精确副本绘制所有权和缓存失效处理，允许模块自身绘制单组来源；安全模式、锁屏、关闭完成或未知来源保持原生。左侧 Phone 小钟和通知假副本在展开超过 20% 时保持空白，保留最后 20% 的原有收起动画。右侧固定横向位置，读取当前分页 helper 的 `ProgressiveProgressDriver.getLogicalOffset()`，使用原生弹簧坐标进行 18dp 上移淡出、下移淡入及反向恢复，不另加定时器。

新运行时 token 为 `c17-runtime-20261002-horizontal-preview3`。相关 Java 8 定向编译通过，新增 `StatusIconTransitionCheck` 的 453 项检查通过，包含实际编译的副本所有权 guard、缓存绑定变化、当前 driver 身份、helper 换绑、反向和取消的 alpha/Y 连续性。此处仍是**源码与定向检查结果**；新包安装、SystemUI 新 token 应答和横切实机复测结论待主代理补录，不能提前写为横切重影已实机修复。
