## 使用范围

- **通知类跟随系统样式**：通知栏和悬浮通知分别采用对应场景的普通通知配方，包含模糊混合、描边和内阴影，并按目标实际宽高适配。使用目标自己的 BlurProxy，不共享其他卡片的 Drawable 或观察器。锁屏使用本场景 WALLPAPER_A/B 的原生锁屏通知配方；AOD、未知进度或接口不可用时保留系统样式。独立音乐主色渐变保留。
- **桌面流体云去高光**（code91 起不再有单独开关）：流体云去高光由“界面材质 → C17 高光去除”统一控制，该功能开启（且“消息通知去高光”未关）时，悬浮展开的流体云卡片同样去除 GLOW 材质混合与独立装饰，保留原生模糊、半径、圆角、内容和交互。旧配置里的该键保留以兼容备份，但不再起作用。
- **音乐媒体保留高光**：只决定音乐卡片是否保留原生高光，需要先开启“C17 高光去除”（否则没有东西可保留，设置页会说明）。开启后，音乐流体云（悬浮、锁屏）保留原生高光，其他流体云仍按 C17 设置去高光。不再依赖“流体云样式”总开关。**只有你自己开启的 C17 高光去除才会去掉锁屏音乐卡的高光**：code91 里“通知类跟随系统样式”在亮屏时会顺带去掉它，表现为息屏显示（AOD）亮屏后高光消失，code92 已修复。
- **自定义底色**：只改填充颜色与透明度，保留原生模糊和动效。底色来源只有两个：**自定义系统样式颜色**（保留原生模糊、渐变与材质，只替换颜色，可调颜色与透明度）和**自定义纯色**。旧版的“跟随系统通知色”“跟随媒体色”两个来源已并入系统样式颜色；旧配置里已生效的媒体色由独立开关“流体云跟随媒体强调色”继续承担。颜色 alpha 与填充透明度相乘一次，原生材质自身透明度保留。作用场景由下面的三个开关决定。
- **流体云跟随媒体强调色**：独立于样式与媒体强调色总开关，使用系统已算好的最新主色。本卡优先，否则使用当前仍绑定的媒体来源；缺少来源时保留原生颜色。共用媒体强调色的遮罩参数，不重新读取专辑像素。旧配置里已生效的“跟随媒体色”迁移到这个开关；旧样式总开关关闭时不会因此启用新功能，显式关闭的新开关也优先于残留旧选项。
- **强调色遮罩**：开启媒体强调色或流体云跟随媒体强调色后可用。颜色叠加到原生最新取色结果上；遮罩透明度为 0% 时不叠加，100% 时完全采用遮罩颜色。选用自定义颜色 alpha 时，颜色 alpha 与此百分比相乘。关闭遮罩恢复最新强调色，参数保留。
- **流体云媒体强调色的作用范围**（没有“作用于锁屏”开关）：只要开启，悬浮展开、锁屏和 AOD 的音乐卡都使用强调色，优先级最高；**通知栏不受影响**。强调色与其他卡片走同一条路径：玻璃材质加填充色，所以音乐卡与秒表等卡片的材质一致（code91 的锁屏专用渐变副本会让音乐卡变成另一种平整的材质，code92 已取消）。关闭、通知换绑或媒体退出后回放最新的原生初始化。

## code91 颜色优先级、作用场景与 AOD

**同一张流体云卡片在任何场景里按同一顺序取颜色**，高优先级存在时低优先级不再决定颜色：

| 优先级 | 功能 | 范围 |
|:---:|------|------|
| 1（最高） | 流体云媒体强调色 | 悬浮、锁屏、AOD 生效，不受下面的作用场景开关限制；只要开启就始终生效；通知栏不动 |
| 2 | 流体云跟随媒体强调色 | 没有自己强调色的流体云卡片使用当前媒体色（真跟随，随歌曲更新）；没有媒体时落到自定义底色；受作用场景开关限制 |
| 3 | 自定义底色 | 自定义系统样式颜色 / 自定义纯色，受作用场景开关限制 |
| 4 | 通知类跟随系统样式 | 只提供材质配方（模糊、描边、混合、阴影），与上面的颜色叠加，不互斥 |

- 填充透明度始终作用在最终颜色的 alpha 上（媒体色也一样），不会因为媒体色优先而失效。
- **作用场景**：流体云外观页有“悬浮展开”（默认开）和“锁屏与 AOD”（默认开）两个开关，决定优先级 2、3 在哪里生效；AOD 跟随锁屏，因为 AOD 是锁屏经原生进度连续过渡来的，同一张卡片在亮屏与熄屏之间必须是同一种颜色。**通知栏没有开关：颜色功能从不改动通知栏**（旧配置里的通知栏开关键保留以兼容备份，不再起作用）。
- **通知类**页面与行为不变；它的“跟随”状态只决定该卡片是否接受 C17 的光学去高光。
- **AOD 不再切换任何层**：进出 AOD 时，卡片保持亮屏时的组合（材质配方、填充、媒体渐变、AOD 遮罩颜色），直到回到亮屏。AOD 遮罩副本的颜色按“强调色 → 自定义/媒体填充 → 亮屏通知色”选取，和卡片本身的顺序一致。统一通知卡片颜色层不再随流体云状态开关。
- **通知也跟随媒体色**：见 [流体云跟随媒体强调色页的“通知卡片”](FLUID-CLOUD-ACCENT.zh-CN.md#通知卡片跟随媒体色code91)，只作用于锁屏与 AOD。
- 锁屏媒体卡片的归属判断增加兜底：卡片内容是远端 Surface、又只有一个媒体来源和一张可见通知时，视为同一张卡片；普通视图树里没有该媒体来源的卡片不会被误染。

## 原生接入与恢复

桌面展开背景沿用 `CardView → CardBackgroundView → BackgroundUtils.b(View, ViewRootManager)`。模块只在这一调用的短作用域内替换背景资源和材料输入，不改变共享资源。`OplusBlurParam` 的 18 个浮点槽克隆后处理：GLOW_OVERLAY 4 改为 OVERLAY 2，GLOW_COLORDODGE 5 改为 COLORDODGE 3；底色来源仅调整填充输入。原生 blurType、tileMode、zoom 和平滑圆角参数保留，半径仍由原生动画设置。

无模糊能力时 manager 可以为空，原生继续使用静态 shape 资源。该分支只私有克隆纯 GradientDrawable/LayerDrawable 树，分别派生填充、描边和强调色，保持各层原生透明度与圆角。独立 `MediaBackGroundView.F` 的 shader 只画阴影、光圈和边缘高光；按精确实例跳过装饰绘制，不删除媒体子 View，不停止取色 flow。

通知本体依据 `OplusCustomRow.mBackgroundNormal` 的真实对象身份登记。初始化、绑定、主题更新和背景替换时读取一次 getter；不在每个绘制帧扫描父子节点。通知栏通过 `ViewBlurManager.CardType.NOTIFICATION` 获得完整配方；悬浮 CUSTOM 行原生 mode 可能未初始化，使用原生 `getBlurModeForRow(null,true)` 得到真实 HeadsUp mode；锁屏使用实际 WALLPAPER_A/B，不采用通知栏 mode。

code82 补齐三个原生后端：Platform 的 mix/stroke/shadow、Motion 的 NOTIFICATION `headsupCardMotionMixConfig` 和 `BackgroundBlurDrawable`、BlendWallpaper 的完整配方和 `BlendWallpaperBlurDrawable`。在绘制外对应的 `applyConfigToPlatformBlur`、`applyConfigToMotionBlur`、`applyConfigToBlendWallpaper` 短作用域内提交，补齐原生 mirrorScale，退出恢复字段。锁屏校验实际宿主、底层对象和已提交 mix；仅创建但未提交的 wallpaper 背景不清模板底板。绘制中已登记目标的原生提交合并到绘制外，避免 CUSTOM 配方重新覆盖缓存背景。只有当前实际后端有效才清额外实色底板，失败保留并恢复原生。配方按材质版本、场景、后端、运动模糊状态和实际尺寸缓存，相同版本和几何不逐帧重试。

锁屏新配方要求已确认 `OplusPanoramicAodRepository.getPanoramicAodProgress()==0` 且非 dozing。只监听实际实现的 `setPanoramicAodProgress(float)`。code86 在 setter 的同步回调之前标记过渡：仅保留已确认成功提交、没有自定义底色或强调色的普通通知 WALLPAPER 配方，系统 AOD drawable 和原生动画继续绘制，过渡中不重建；回到锁屏后刷新一次。未知进度、未确认的配方及独立底色/强调色继续回退原生。实际行的 WALLPAPER_A/B 配方有效时不再被全局通知面板 SHADE mode 错误拒绝。没有拦截全局 StateFlow，也不在稳定帧轮询进度。

锁屏强调色沿用真实 entry 注册链。旧通知 MetaBall 在沉浸展开终点 alpha 为 0；单独修改它无法显示锁屏取色。实际可见的 `OplusCustomRow.immersiveCustomDrawable` 由原生 `SmoothRoundExKt.getSmoothDrawable` 创建，为标准 GradientDrawable。模块只对这一对象创建私有 TOP_BOTTOM 渐变副本，去除副本的纯色 tint，保留原生圆角，每帧仅同步其动画 alpha。副本只在对应背景的绘制作用域替换，退出立即恢复原对象；未知背景保持原生。原生 MetaBall 的交叉渐变仍保留，不在绘制时重新取色、创建副本或提交模糊。

普通通知和 shader 材质中的 top/bottom 混色表示独立叠色，不能用来表示空间渐变。底色调整使用独立混色副本，并保留原生动画、镜像和占位属性。模板附加底层只在实际背景提交成功后清除；失败保留原生。封面、文字和按钮不参与替换。关闭时按最新 entry 恢复，不回滚到旧专辑颜色。`immersiveFullBg` 用于锁屏沉浸背景，不能当作下拉通知本体处理。

原生托管内容通过 SurfaceControlViewHost 的绑定事件建立归属；SurfacePackage 副本按原生层身份比对，不按 Java 对象相等或全局最新颜色猜测。SurfaceView 的 detach 和 host 释放清理归属。`PageBackgroundView` 的光斑不再作为锁屏卡片底板进行实色过滤；去高光与主色渐变分开处理。旧媒体实例退出不移除新实例已经接管的共享背景。

关闭功能、安全模式、退出或替换背景时恢复其原生材质。退出卡片时两个控制器共同进入原生恢复作用域，避免恢复过程互相重新上色或重新登记已退出的背景。素材与取色观察器保持原生生命周期。

## 开销和兼容性

code83 移除了“白色信息跟随系统变动”，文字与图标颜色交回系统。旧配置、框架快照及配置导入中的该选项均强制关闭，保留历史字段类型以兼容完整配置；不再注册全局文字颜色和图标 tint 的拦截。

系统默认底色也支持填充透明度。资源色已调节时，硬件参数不再重复乘透明度；硬件独立输入与静态背景则各自处理一次。静态原生渐变先复制色数组，避免修改共享原色。通知和锁屏的底色作用于已确认的实际模糊后端，独立媒体强调色保持优先。

code85 补上桌面 `SeedlingCard` 展开背景的通知类跟随入口，使用当前普通通知的颜色并取消模板附加渐变。它与通知本体使用不同材质后端，悬浮效果是否与普通悬浮通知完全一致仍需实机对照。硬件独立输入现在也应用底色透明度；资源已经应用时保持一次，静态私有副本取消会盖住自定义填充的旧 tint。

锁屏媒体归属补齐包装容器与已登记 Surface 内容的对应关系；反射合同同时按实际定义类的 ClassLoader 登记。诊断仅记录有限次场景、配方、后端、尺寸及颜色资格，不记录通知内容。稳定帧不新增取色、模糊提交、定时器或全树遍历。

强调色仍读取系统已经计算的媒体主色。遮罩只在原生背景初始化时混合 RGB；不重新提取专辑像素、不定时轮询。相同场景、颜色、参数及设置复用缓存，实际变化才刷新；关闭后恢复自己的原生材质，不修改其他卡片。

旧版已开启“去底色”的配置升级为自定义底色、填充透明度 0%，保持原有透明效果。新版首次开启采用系统默认、100%；来源与透明度在同一次保存中固定。关闭功能不删除参数，也不重置其他用户配置。页面分为“通知类”和“流体云外观”。

支持范围基于已经查验的 ColorOS 17 接口。不同固件缺少真实类、方法、字段或参数结构时保留原生；没有声称覆盖未知材质引擎、所有第三方界面或通知应用自己绘制的颜色。桌面去高光覆盖本链路的 GLOW 和独立装饰渐变，保留已启用的媒体主色渐变，不涉及内容图标自身的光学绘制。

编译和桌面回归不等于实机效果验收。需检查通知主题切换、媒体换曲、各开关恢复以及展开/收起动画；GPU 时延和耗电尚未实测。

## 大时钟边界的流体云模糊

`OplusCustomRow` 的实际高度和裁切参与普通通知的空间边界。Surface 不属于这一 Canvas 捕获：已确认本进程内容使用复用的局部 RuntimeShader 并串接原生 RenderEffect；外部内容使用原生 OplusNotificationTiltShiftBlurContainer 的背景模糊合同，效果层限定于真实卡片与边界的交集。外部缓冲是否被设备的合成器纳入这一背景模糊，仍需视觉确认，不由桌面 fixture 推断。

draw 只提交最新几何。ViewRoot 写入、overlay 增删、测量、布局和材质应用在合并后的主线程任务执行，不在父树绘制中改树。最多四个有效交集；带外 Surface 不消耗名额。相同几何和材质不重建或重排，卡片替换、弱引用回收、分页、关闭和 detach 释放自己的效果，不删除系统 overlay。原生合同不可用时保留系统绘制。

## 桌面悬浮展开的普通通知材质（code86）

这一背景独立于 NotificationBackgroundView 的 BlurProxy。通过已经登记的原生背景 extension 取得 NotificationMaterialColorEx、真实 HEADS_UP mode 与 ViewBlurManager，使用 `headsupCardMotionMixConfig(NOTIFICATION, mode)`，再由 `ViewBlurProxy.buildMotionBlurParam(MixColor, Float)` 生成原生参数。完整替换两层混色、透明度及 blur type，保留桌面宿主的 tile mode、zoom、smooth corner、尺寸和动画。只有有效参数存在时才清模板额外渐变；缺少合同时保留系统背景，并不影响已正常的通知栏和锁屏实现。

工厂配方按材质版本缓存，实际主题和悬浮状态事件使缓存失效；绘制不调用工厂，不定时扫描。AOD/锁屏不重建隐藏桌面卡片。新增两组回归的范围及实机边界见 [code86](LOCAL-CODE86.zh-CN.md)。

## code87 作用范围与 AOD 遮罩

流体云外观去高光、底色来源/透明度及独立跟随媒体色只作用悬浮展开。NotificationBackgroundView 不再使用外观填充；已登记的本进程 Surface 内容也按通知归属隔离，进入通知/锁屏场景恢复其原生初始化。通知类跟随、独立媒体强调色作用于锁屏仍由自己的入口控制。

ColorOS AOD 原生 applyMask 会单独提交 OplusAodRowBackgroundDrawable 黑色层。保留 BlurProxy 不足以解决黑底。code87 仅在精确原生 setter 事件中创建并复用每行私有同类圆角 mask，使用亮屏通知材质色或已启用锁屏媒体强调色，保留原生 alpha 与几何；不改原生共享遮罩。关闭、清除、未知材质及解绑恢复原生。稳定绘制无颜色查询、通知扫描或材质提交。真实 AOD 和功耗仍待手机确认，见 [code87](LOCAL-CODE87.zh-CN.md)。

## code88 外观与原生底色编辑

外观作用范围按真正 OplusCustomRow 父链和当前可见、已附着的通知 Surface 判断，不再使用可复用的 entry 内容引用。未编辑的系统默认来源保留原生RGB；明确保存颜色后可调整颜色与透明度，保留原生模糊、渐变和动效。编辑标记兼容旧镜像，并随导入导出和当前页恢复默认处理。

独立跟随媒体色优先决定RGB及其遮罩；开启自定义底色时，填充透明度仍会作用到媒体色上。媒体取样不会停止。资源/硬件/static fallback 的配置alpha只应用一次，静态回放先处理媒体色、最后处理外观。外观仍只作用悬浮展开，通知栏与锁屏由各自通知跟随/媒体开关处理。见 [code88与检查清单](LOCAL-CODE88.zh-CN.md)。
