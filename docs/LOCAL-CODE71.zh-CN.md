# 1.8.1 / code71 本地修复

本次针对 code70 的实际反馈修复。手机当前安装 code70；用户要求先只读取数据，稍后测试。因此没有切换页面、修改配置、安装、重启 SystemUI 或进行锁屏/AOD 手势验证。

## 时间消失

实际 SystemUI dump 中，StatClock 仍为 VISIBLE、alpha=1，但 measuredWidth 和 actualWidth 都为 0；外层已经分配 666px，扣除 78px padding 与 230px 通知区域后，仍有 358px。不是隐藏开关或真实空间为零。

原生 StatClock 的 onMeasure 会用自己的 actualWidth 生成 EXACTLY 约束，忽略传入的旧 childSpec。模块再将历史 childSpec 的 0 宽作为二次上限，写回 actualWidth，造成反馈循环。现在只有确认原生四层父结构时，直接以实际字宽和外层剩余预算测量；未知父结构、没有已分配宽度或预算确为 0 时仍遵守原生约束。

保留比例、字重、字体和位置。100% 继续对应原生 px 基线，不重置配置，也不强制压低用户比例。扩大时仅限制时间自己的槽位，继续保留通知图标空间。

尺寸诊断增加 incomingMode、incomingWidth、nativeMeasuredWidth、nativeActualWidth、outgoingWidth；只在尺寸改变且启用诊断时记录，不记录时间文字或通知内容。

## 位置与配色

网速在原生位置且关闭安全间距时，只调整自己的偏移，不再重排 Wi-Fi 和蜂窝信号。测量期间将相邻图标的占位与网速自己的测量分开，不让外层预留量进入子控件测量。Wi-Fi 隐藏时按网络区域净缺口保留锚点，已出现的 4G/5G 文字槽位不重复占用空间。

开启现有安全间距后，按网速、Wi-Fi 和蜂窝图标的实际宽度、缩放与独立水平偏移计算边界；蜂窝主信号按其 20dp Compose 槽位定位，不采用包含网络文字的整个宿主中心。安全间距保持用户原有开关，不自动开启、不重写偏移值。关闭与重开、Wi-Fi 切换后重算安全占位，保留同一原生 View/state 的基线；替换或移除视图时重新采集。

控制中心设备卡片按普通未激活磁贴的原生材质规则处理，不再另设一条透明底色或强行套用活动磁贴颜色；设备行与普通磁贴的关闭恢复、裁剪和交互仍使用各自原生路径。

实际日志中的 SysUiTileBg 后台线程界面更新错误已修复：按 View 合并注册与刷新到主线程，取消每次注册的无条件失效。后台玻璃内容失效只请求主线程绘制。颜色变化以实际原生事件触发，不增加刷新轮询。

## 锁屏模糊

区域模糊跟随原生 behind/front scrim 的实际 Drawable opacity 与连续 doze 值，系统把壁纸遮黑时同步撤销模糊区域。仅观察真实壁纸 scrim，不改系统遮罩，不读取通知卡片遮罩，不增加轮询或自有动画。
