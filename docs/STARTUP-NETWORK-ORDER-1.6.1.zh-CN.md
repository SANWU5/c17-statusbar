# 1.6.1 开机加载与网络图标顺序

当前本地续作版本为1.6.1 / versionCode 58，尚未上传或公开发布。本文说明保存、开机通道和网络顺序；完整新功能见 [code58 用户说明](LOCAL-1.6.1-CODE58.zh-CN.md)。本轮构建、回归和实机结果待最终复核，下面code52/53问题与修法保留历史含义，不代替code58验收。

## 开机加载

原实现只在SystemUI首次绑定时读取一次配置。code52增加观察器及有界补读，但真实整机重启仍失败：ColorOS阻止SystemUI通过ContentProvider唤醒模块应用，日志明确记录了应用启动拦截；用户解锁后的重试同样可能被拒绝。增加重试不能解决这类限制。

code53通过官方libxposed服务，将确认写入成功的完整配置同步到框架。SystemUI启动时优先从框架直接读取快照，避免唤醒应用；应用私有设备保护存储仍是配置保存来源，升级后正常打开应用即可同步已有配置。首次失败后有界退避补读，开机完成、用户解锁和真实配置变化也会触发，成功后停止。重复绑定界面不会持续重开重试窗口，旧异步结果不会覆盖新设置。没有新增自动重启SystemUI、Root后台服务或常驻轮询。

框架快照校验schema、完整类型及保存标识，缺失或损坏时不合成成功配置。本轮只对完整旧code57快照补入本轮新增默认值，不接受缺旧项或仅部分新项的快照；新横屏主开关仍默认关闭，保存值不被自动改写。数值试用期间不把临时值写成开机快照；真实设置通知优先读取应用配置，建议范围外手工数值继续20秒确认。配置服务暂时不可用时保留已确认快照。

保存的功能开关与参数按原值加载，安全模式继续有效，不会自动打开原来关闭的功能。模块仍须在LSPosed中正常启用并选中SystemUI。

## 配置保存与恢复

主配置和恢复备份继续使用应用私有的设备保护存储，保持已有XML格式；卸载时随应用数据删除。配置缺失或服务暂时不可读取时，不用默认值覆盖已保存的内容。存在错误类型的配置不会被包装成新的完整快照。

即时参数修改仍可及时反映到界面，后台合并检查实际写入结果。恢复备份只接收确认写入成功、且期间未被新编辑替换的配置；稳定读取相同配置不会反复写备份。明确失败的同步保存或导入会保留本次编辑前的值，失败结果不会当作成功配置发送给SystemUI，界面提示重新保存。恢复空配置也须确认提交成功后才记录恢复成功。

## 网络图标顺序

入口：配置 → 状态栏 → 网络信号 → 网络图标顺序。

此开关默认关闭，独立于Wi-Fi和蜂窝图标样式开关。开启后将Wi-Fi图标或4G/5G网络文字与蜂窝信号调换位置；各自的大小、颜色、字体和自定义位移继续保留。自定义位移叠加在新顺序上，过大的位移可能使图标重叠。关闭、安全模式与解绑后恢复原生顺序。

原生测量、边距、RTL方向和状态动画继续负责实际布局，未知结构保持原生显示。

## 底栏与磁贴性能

普通底栏使用不透明背景覆盖整个系统手势区域，只有图标和文字避让安全边距，消除横条后露出页面内容的问题。选中项使用浅色圆角背景及短颜色过渡；内容尾距跟随底栏实际高度，支持较大字体。键盘显示时隐藏底栏，弹窗仍由最上方独立视图承接。

透明磁贴复用尺寸与坐标匹配的渐变、绘制临时缓存和未变化的材质着色器源码，关闭诊断时不拼接绘制日志。尺寸、主题、配置或材质结构改变时重新计算，原生颜色、透明度、按压动画及光学参数仍按需更新。原生模糊和透明叠加仍有GPU成本，桌面重复调用计数不能代替实机帧率或耗电测量。

## 通知堆叠

状态栏 → 通知显示提供“堆叠通知”和“同类通知堆叠”，两者默认关闭、独立于大时钟，可同时开启。前者沿用原整体Stack主开关、处理外层列表；后者只折叠系统已有消息组，不把不同应用独立通知混成组。保留真实通知、尺寸、长按、滑除及展开，最新依据系统收到时间。关闭或安全模式恢复原生；本轮实际交互表现待复核。
